# 全流程操作手册

## 1. 选题与搜集

可从用户指定新闻、官方订阅、公开科技媒体、社区讨论或已有热点源发现线索。外部热点 API 只提供线索，凭据独立配置，不把其排名当真实性证据。记录检索时间，优先官方公告、论文、模型卡、财报、原始采访。其他 AI 的带引用总结需逐条打开原网页，检查结论是否真被支持。

每篇在 `work/<slug>/` 建独立目录，包含 article.html、article.json、cover.png、正文图、sources.md、review.md 和私有回执；不用通用 article_daily 文件覆盖多篇内容。

定时任务只做到“发现线索→证据表→本地待审初稿→通知待审”；调度器、热点服务与模型工具由使用者选择。保存检索窗口、来源、失败状态，重复线索去重。没有明确自动发布授权时不把调度任务连到草稿写入或群发。

## 2. 写作与校对

先验证选题前提，再写主线与章节。参考 STYLE_DNA；价格比较统一币种、时间、缓存、峰谷时段、计价单位；跑分注明基准版本、官方/第三方和测试条件。时区转换后再写同日/隔日。

生成初稿后分别检查事实、叙事和版式。校对结论留 review.md；读者正文写准确事实。标题锁定也不能保留事实硬伤。来源不足则说明，不能编造事件、人物引语或因果。

## 3. 配图

先写每张图要解释的问题，再选官方截图或生成概念图。第三方截图核对来源、可使用范围与必要裁切；不要把生成界面、签约合影当新闻证据。每张图保留说明、来源和生成提示词。复杂数据图使用可靠绘图工具精确排版；不让生图模型决定数字。

逐张检查：文字、人数、坐标、时间顺序、主次、手机可读性、相邻图是否重复。保留原图，压缩和裁切另存副本。必要生成标识与来源不能用补色块覆盖。单图内容走第 8 步。

## 4. 排版与本地验证

先用 inline_css.py 处理嵌入样式，再更新清单的 source；publisher check 会拒绝残留 style/script、正文 h1、原生列表和外部图片。图片需本地保存后统一上传；每个 img 填 alt。例子中的紧凑行距不是视觉检查替代品。

在手机宽度预览：长标题/链接不溢出、表格与数据清楚、图注贴近对应段落、不出现空圆点。无法预览时明确记录“只完成结构检查”。

## 5. 同步与草稿

按 DEPLOYMENT 配好固定出口服务器，先运行 remote.sh sync。同步只传当前清单和必需文件，不传密钥、不删除远端文件、不覆盖回执。确认清单对应正确文章后，用户授权创建时运行 create，授权覆盖时运行 update。

create 上传封面永久素材、正文图片并替换 URL，再 draft/add；update 使用同一回执里的 media_id 执行 draft/update。两者都 draft/get 回读比较标题、封面、正文文本和图片数。回执记录全部素材指纹、上传映射、写入状态与验证结果。

## 6. 修订与异常恢复

正常修订沿用同一清单和回执，执行 update。变化后的正文图将使用新的上传映射。超时、断网、进程退出先检查 RECOVERY，不清除状态后盲重试。永久素材可能留在后台，清理需明确列出对象并另行授权。

## 7. 正式发表与群发

草稿创建不等于公开发表；发表与向粉丝群发也不能混用。先检查账号实际能力和当前官方接口规则。旧记录中的 48001 只代表当时账号/接口权限不足。

此工具不提供正式发表或群发命令。用户要求后，到公众号后台按标题和草稿 ID 定位，核对最终正文、封面、图片、预览与目标受众，再按其指定操作提交；后台需要扫码/登录时由账号拥有者完成。最后以后台状态或可访问文章确认，不能把“已点按钮”当作成功。

## 8. 单图/贴图路径

先核实图中数字、型号和来源。用户要图文草稿时，用一张正文图及独立封面按普通链路创建；用户明确要后台“图片”类型时用后台相应类型，不声称通用图文 API 就能替代。准备简短标题与描述，若后台无法控制，交付图片、标题、描述并准确说明尚未发布。

## 9. 交接

复制公开模板和自己的私有 work 素材，凭据与 SSH 单独安全迁移。保留服务器上的回执与历史指纹。先 check，再 sync，再执行经授权的草稿动作；先验证恢复路径再接自动化。
