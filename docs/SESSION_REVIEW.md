## 检查范围与证据

检查了项目关联的三个历史会话：`分析当前项目`、`分析当前项目 (2)`、`发布微信公众号贴图`，以及当前整理请求。应用中检查了活跃与归档列表；本地会话索引显示三个历史会话关联本项目目录。

会话读取工具对部分大轮次报大小限制，因此补读了对应的 8 份本地记录文件；去除完全相同的消息后，提取 514 条用户/助手文本消息。范围覆盖 2026-08-08 至 2026-10-09 的关联历史，包含分段续写记录。记录不是 514 个独立请求，也不是对外发布的聊天导出。附件视觉内容、已丢失临时文件、外部未关联聊天不在完整性承诺内。

同时检查项目交接文档、文风库、发布/更新脚本、同步脚本与辅助处理程序。历史助手曾说“已核实”或“已成功”只能证明会话里这样记载；本次不据此重新认证历史新闻，也未重连真实公众号验证旧草稿。

## 流程演进

| 阶段 | 记录中的问题与变化 | 公开版处理 |
|---|---|---|
| 初期 | 临时目录里残留旧草稿、上传与组装顺序耦合，同标题多份草稿 | 文章独立目录、按清单组装、回执与提交状态持久化 |
| 内容校对 | 型号混淆、融资目标被当到账、同一事件日期因时区误判 | 一手来源表、型号/时间/金额检查 |
| 图片修订 | 生成乱码、错误时间线、伪合影、两图重复、涂色补丁 | 官方图优先、概念图归属、数值确定性绘制、逐图验收 |
| 排版收紧 | 正文重复标题、行距偏大、原生列表空圆点 | 无正文 h1、行高约 1.5、段距约 9px、手机预览 |
| 固定出口 | 本地网络变动反复触发白名单错误 | 本地写作，服务器调用微信，凭据服务器独立保存 |
| 草稿更新 | 同一文章反复修改，网络中断状态不明 | 同一 ID 更新、记录 in-flight、回读核验，禁止盲重试 |
| 交接迁移 | 需交给新电脑与其他 AI | 环境模板、部署流程、职责与授权边界 |
| 正式发表/贴图 | 草稿可用不代表正式发布权限；接口曾返回 48001 | 写清后台发表/群发与单图内容的人工完成路径 |

## 需要保留的判断

1. 标题与图片必须围绕新闻主线；补充材料不能取代主题。
2. “去 AI 味”依靠具体事实、删重复与自然表达，不能以此删除关键限制或保留错误标题。
3. 回读成功是草稿完成证据；上传图片成功不能替代正文、封面、标题核验。
4. 不能仅凭本地 HTML 存在、图片 URL 存在就宣称微信显示正常；需要后台查看。
5. 固定 IP 解决出口变化，不自动赋予正式发表权限。
6. 一些旧脚本只计算 HTML+封面指纹，漏掉正文图变化；公开版指纹包含清单与全部本地素材。

## 不是已经实现的能力

选题搜集、事实判断、写稿、视觉验收与后台最终发表仍是 AI/人工协作步骤。历史提及自动化选题来源，但本地没有一套经本次验证的完整调度服务；公开版提供调度输入输出约定，不虚构可一键运行的热点接口或自动群发系统。
