# 回执与异常恢复

- `40164`：核对真正调用微信的服务器出口与后台白名单。不要因为笔记本换 Wi-Fi 就添加无关地址。
- `48001`：检查账号与接口能力；保留草稿。没有权限不能报告公开发表成功。
- 作者字段拒绝：作者可选，先核对平台长度规则，必要时清空。不要打印完整请求 URL 或 token。
- 中文变成转义串：以 UTF-8 序列化 JSON，禁止二次 json.dumps；回读实际标题。
- 图片地址属性转换：微信可能使用 data-src 等属性；回读时同时识别，后台预览确认真实显示。
- 标题正确但图片数量/正文不符：保留回执，不标为 verified；检查本地清单、内联源文件和后台是否有人修改。
- 草稿 ID 失效：在后台定位实际草稿，不凭同标题猜测。人工核对后建立对应关系，不能自动新建替代。

## 提交状态不明

写请求前回执先标记 `in_flight`。请求失败不代表平台没处理。重新执行会停止，不能删回执来绕过。

创建中断：后台按时间、标题、封面核对是否存在；找到后核对 ID 并用维护者受控方式恢复回执，再回读。确认根本没创建后才清除 in_flight 重试。工具刻意不自动按标题绑定，避免误改同名文章。

更新中断：已有 media_id 不变。先在后台检查当前稿与预期版本，确认完成则用 `verify` 回读；verify 会清除相应的 in_flight。若仍是旧版，应人工记录确认结果后再处理回执并重新授权 update。

`python scripts/publisher.py verify path/to/article.json` 是读取动作，必须有与当前指纹一致的回执以及 media_id。它不上传素材、不创建/更新草稿。

## 并发与回执

工具用独占锁避免同一回执并发写入。进程异常退出可能留下 `.lock` 文件；先确认没有正在运行的任务，再人工移走锁。回执采用原子替换，保存前权限 600。远端备份不得被全量同步删除。

## 旧项目教训

不要用共享 `/tmp/draft.json`、通用 article_daily 文件或固定三个 IMG 占位把不同稿件串在一起。不要在网络中断后循环 draft/add。不要把“上传成功”“请求发出”写成“草稿核验成功”。
